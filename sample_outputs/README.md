# Sample Outputs Guide

This guide describes artifacts generated by `scripts/run_pipeline.py` and how reviewers should interpret them.

---

## 1) `routing_metrics.csv`
- **When generated**: every run that creates routed outputs.
- **Metric type**: mixed (observed routing rates + estimated cost fields).
- **How to interpret**:
  - Use stage/queue rates for routing behavior summary.
  - Treat cost columns (e.g., `cost_per_ticket_usd_estimated`) as assumption-based estimates.

## 2) `threshold_sweep.csv`
- **When generated**: every run.
- **Metric type**: estimated.
- **How to interpret**:
  - Compare auto-route, LLM fallback, and human-triage rates across threshold choices.
  - Use recommendation-related columns as analytic policy guidance, not guaranteed optimum.

## 3) `routing_policy_recommendation.csv`
- **When generated**: when threshold sweep produces a recommendation row.
- **Metric type**: estimated.
- **How to interpret**:
  - One-row policy guide for discussion.
  - Not automatically applied by pipeline and not a claim of global optimum.

## 4) `eval_comparison.csv`
- **When generated**: only when `data/eval/eval_tickets.csv` exists.
- **Metric type**: measured.
- **How to interpret**:
  - Summarizes ML vs keyword baseline with accuracy and F1-family metrics.
  - Use for evidence of incremental model signal over heuristic routing.

## 5) `eval_per_class_metrics.csv`
- **When generated**: only when eval set exists.
- **Metric type**: measured.
- **How to interpret**:
  - Per-class precision/recall/F1/support by model.
  - Useful for identifying class imbalance and weak class performance.

## 6) `eval_confusion_matrix.csv`
- **When generated**: only when eval set exists.
- **Metric type**: measured.
- **How to interpret**:
  - Class-level confusion counts in long format.
  - Use with dashboard heatmaps to inspect misrouting patterns.

## 7) `training_report.txt`
- **When generated**: every run.
- **Metric type**: mixed (measured train/test + CV stats, plus textual summaries).
- **How to interpret**:
  - Consolidated training/evaluation log across issue/urgency/complexity targets.
  - Complexity remains a heuristic proxy label in this repository.

---

## Measured vs Estimated vs Proxy (quick reference)
- **Measured**: computed from labeled ground truth (e.g., eval comparison/per-class/confusion artifacts).
- **Estimated**: derived from assumptions or confidence simulations (e.g., threshold sweep costs/policy guide).
- **Proxy**: heuristic-derived signal where semantic ground truth is unavailable (e.g., complexity label).
